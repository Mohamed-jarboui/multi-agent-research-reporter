# R3 design: benchmark harness

**Goal.** Compare the single agent (`baseline`) and the multi-agent system (`multi`) on 12 topics x 2 runs each: coverage, citation validity, pairwise judge, tokens, cost, latency. The free-tier quota is the bottleneck, so the harness is resumable, quota-aware and honest about failures.

Code lives in `src/reporter/bench/` (importable and tested); `evals/*.py` and `reporter bench ...` are thin entry points.

## Files and commands

| Module | Role |
|---|---|
| `topics.py` | `evals/topics.jsonl` -> `Topic(id, topic, domain, must_cover)`; validated (unique ids, 3-5 points, 12 lines by default) |
| `records.py` | `RunRecord`: one JSON per (topic, system, run index) in `results/benchmark_runs/` |
| `runner.py` | the loop, preflight, stop rule (`run_benchmark.py`) |
| `scoring.py` | citation check, coverage (LLM + quote check), pairwise judge |
| `aggregate.py` | `results/benchmark.json` (`aggregate.py`) |
| `pairs.py` | `make_pairs.py` (6 blind pairs for the owner), `judge_pairs.py` (judge + agreement with the owner) |

## Run records and resume

Raw traces go to `runs/benchmark/` (git-ignored). The record holds status (`success`, `failed`, `not_run`), reason, limit type, the report text, tokens, cost, latency, models, citation check and coverage, so it can be committed (the `results` branch) and used without the trace. A re-run skips `success` and `failed` records; `not_run` ones are redone; `--retry-failed` redoes failures. Order is interleaved per topic: for each topic and run index both systems run, the first one alternating, so quota exhaustion does not favour one system.

## Success, failure

Success = the run returned and wrote a report: baseline read at least one page; multi has `trace.writer.status == "ok"` (the digest fallback and the "no report" text are failures). Any failure is recorded with `reason` and `limit` (most telling limit type in `trace.llm.limits`, a daily one first). Failed runs are never dropped: they stay in attempted counts, in cost and in cost per successful report.

## Quota rule

Preflight: `ping_all` once. Every configured provider failing with a per-day limit stops the run before it starts; no provider configured is an error (exit 2). After each run, providers that returned `per_day_tokens` or `per_day_requests` 429s are added to a session set; when the set covers all providers of the run, the script stops: the remaining planned runs are written as `not_run` with the reason and the exit code is 3. Also stops after N consecutive failures (default 6). `--max-runs`, `--topics`, `--systems`, `--runs-per-topic`, `--dry-run` (prints the plan, calls nothing).

## Scoring

- Citations (no LLM): `check_citations` on the report body with the run's own sources and fetched URLs. Valid citation = cited number that exists and whose URL was fetched. Rate = valid / cited; also the share of reports with no problem (invalid, uncited, unfetched).
- Coverage: one compact LLM call per report with the points as a numbered list, returning `{"points": [{"n", "matched", "quote"}]}`. The quote must occur in the report (whitespace, case, quote and dash normalised, at least 20 chars) or the point is not covered. A scoring failure leaves `coverage: null` and is retried on the next invocation.
- Judge: for each (topic, run index) with both successes, A/B order from `Random(f"{seed}:{topic}:{k}")` (seed recorded), system names hidden, prompt says to ignore length, reports capped at 1,400 words (flag recorded), word counts recorded, verdict `{winner: A|B|tie, reason}`. Optional position-swap check (`--swap-check`, off by default): inconsistent answers become a tie. The judge model is recorded; `same_model_as_writer` flags self-preference risk. Judge providers default to Groq first (the writers try Gemini first).

## Aggregation (`results/benchmark.json`)

Per system: attempted / succeeded / failed / not_run (grid minus records), failure reasons and limits, coverage rate (overall and per topic, successful runs scored), citation rate and clean share, tokens (total, per successful report), cost (`cost_usd` as recorded; the list-price equivalent only when every model used has a non-zero price in `pricing.py`, else `not_measured`), latency p50/p95 over successful runs (p95 flagged meaningless below 20 runs), cost per successful report = all attempted cost / successes. Judge: wins, losses, ties, n. Every figure carries its `n`; gaps go in `not_measured`; nothing is estimated.

## Owner calibration

`make_pairs.py` picks up to 6 pairs (distinct topics first, seeded), writes `evals/pairs_to_rate.md` (no system names) and `evals/pairs_key.json`. `judge_pairs.py` judges them in the owner's A/B order and, if `evals/pairwise_human.jsonl` exists, reports agreement with n; otherwise "the judge is not calibrated".

## Workflow

`.github/workflows/benchmark.yml`: `workflow_dispatch` with inputs, `contents: write`, checks out the `results` branch data first so the run resumes, runs the benchmark with secrets as env, commits `results/` to branch `results` (always, even on the quota exit code 3). Timeout 340 min.
